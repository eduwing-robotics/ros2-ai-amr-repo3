# 위치추정 기술 발전과 운용 설계 변화

> 위치추정 기술과 운용 설계의 변화를 보존한 기록이다. 현재 기준은 [Nav 문서](../docs/README.md)를 따른다.

기준일: 2026-07-20

## 1. 핵심 정리

위치추정 개선은 두 방향으로 진행됐다.

1. **기술적 튜닝**
   - 지도와 LiDAR 점 사이의 단순 거리 비교에서 시작했다.
   - 이상치에 강한 손실함수를 도입했다.
   - 의미 없는 점을 제거하고 벽 선분을 관찰 대상으로 사용했다.
   - 전역 후보 탐색에도 벽 선분 필터를 적용해 사람과 짧은 불연속 관찰을 먼저 제외했다.
   - 거리뿐 아니라 벽 방향, 연속 선분 이탈, 시간적 일관성까지 평가했다.

2. **엔지니어링적 타협**
   - 계산량이 큰 지도 전체 탐색은 초기 위치를 모를 때만 사용한다.
   - 첫 scan만 지도 전체를 탐색하고, 다음 scan은 상위 후보만 다시 평가한다.
   - 후보 계산은 같은 탐색 격자를 유지한 채 NumPy 일괄 연산으로 바꿨다.
   - 주행 중에는 AMCL과 상태 검증을 사용하고 연속 scan-map 보정은 끈다.
   - 수렴 조건은 정확도만 높이는 방향이 아니라 속도와 현장 노이즈를 함께 고려해 조정했다.
   - EKF는 선택 기능으로 남기고 기본 운용에서는 제외했다.

현재 구조는 **벽 구조로 전역 후보를 빠르게 만들고, 강건 손실과 시간 합의로 후보를 검증한 뒤 AMCL에 넘기는 방식**이다. 위치가 확정된 뒤에는 검증된 AMCL 경로만 유지한다.

## 2. 출발점: 초기 위치에 의존하는 AMCL

기본 위치추정기는 Nav2 AMCL likelihood-field 모델이다.

| 항목 | 설정값 |
| --- | ---: |
| 최소 파티클 수 | 500 |
| 최대 파티클 수 | 2,000 |
| 최대 LiDAR beam 수 | 60 |
| 이동 갱신 거리 | 0.03 m |
| 이동 갱신 각도 | 0.03 rad |
| 위치 분포 오차 | 0.05 |
| 위치 분포 신뢰도 | 0.99 |

AMCL은 초기 자세가 실제 위치에 가까우면 안정적으로 수렴했다. 반대로 초기 위치를 모르거나 잘못된 위치가 입력되면 수렴 시간이 길어지고 잘못된 위치에 머무를 수 있었다. 7월 7일 현장 기록에서도 위치추정 불안정 상태를 수동 initial pose `(0.14, -0.41)`로 복구한 뒤 주행 검증을 이어갔다.

초기 개선 목표는 AMCL을 교체하는 것이 아니라 **AMCL이 수렴할 수 있는 초기 자세를 자동으로 찾는 것**이었다.

## 3. 기술적 튜닝 변천사

### 3.1 모든 LiDAR 점을 사용하던 방식

초기 정합 기준은 변환된 LiDAR 끝점과 지도 장애물 사이의 평균 거리였다. 자세 후보를 \(p\), 각 LiDAR 끝점과 지도 벽 사이 거리를 \(d_i(p)\)라고 하면 기본 평가는 다음과 같다.

\[
L_{\text{trunc}}(p)
= \operatorname{mean}\left(\min(d_i(p), 0.30\text{ m})\right)
\]

거리 오차는 30 cm에서 제한해 하나의 큰 오차가 전체 점수를 지배하지 않도록 했다. 그러나 사람, 적재물, 반사 노이즈처럼 지도에 없는 관찰이 많으면 평균값 자체가 흔들리는 문제가 남았다.

### 3.2 의미 없는 점 제거와 선분 관찰

정밀 탐색에서는 모든 점을 같은 가치로 사용하지 않는다. 연속된 점을 선분으로 분리한 뒤 벽으로 볼 수 있는 관찰만 남긴다.

| 선별 기준 | 현재값 |
| --- | ---: |
| 최대 LiDAR 사용 거리 | 3.0 m |
| 점 사이 분할 간격 | 0.12 m |
| 직선 이탈 시 재분할 기준 | 0.03 m |
| 선분 최소 점 수 | 6 |
| 선분 최소 길이 | 0.25 m |
| 직선 fitting RMS 한계 | 0.02 m |
| 전역 탐색 최대 점 수 | 180 |
| 지역 탐색 최대 점 수 | 240 |

이 과정은 사람을 인식해 제거하는 방식이 아니다. 짧거나 굽어 있거나 불연속적인 관찰을 제외하고 지도 벽과 비교할 수 있는 기하 구조만 선택한다. 테스트에서는 35 cm 크기의 곡선형 외란이 섞인 입력에서도 벽 관찰의 90% 이상을 유지했다.

### 3.3 이상치에 강한 손실함수

이상치 영향을 줄이기 위해 trimmed Huber 손실을 도입했다.

| 항목 | 현재값 |
| --- | ---: |
| 거리 제한 | 0.30 m |
| Huber 전환점 | 0.05 m |
| 제거 비율 | 오차가 큰 상위 12% |
| 최종 사용 비율 | 88% |

상위 12%의 큰 오차를 제거하면 사람이나 적재물처럼 지도에 없는 물체가 자세 평가를 지배하는 현상을 줄일 수 있다. 테스트에서는 매 10번째 LiDAR 점에 35 cm 이상치를 넣어도 위치 오차 5 cm, 회전 오차 2도 이내로 자세를 복구했다.

### 3.4 Hybrid 손실

이상치를 모두 무시하는 방식에도 문제가 있었다. 길게 이어진 실제 벽이 잘못 정렬되면 여러 점이 동시에 큰 오차를 가지는데, trimming만 사용하면 이 관찰 전체가 제거될 수 있다. 정밀 탐색에서는 두 손실을 함께 사용한다.

\[
L_{\text{geometry}}
= 0.8L_{\text{trimmed-huber}}
+ 0.2L_{\text{truncated}}
\]

- 80%: 동적 장애물과 개별 이상치에 강한 평가
- 20%: 제거된 관찰에도 최소한의 책임을 부여하는 전체 거리 평가

전역 coarse 탐색은 벽으로 볼 수 있는 연속 선분과 trimmed Huber 손실을 사용한다. 사람, 짧은 곡선, 불연속 반사는 후보 탐색 전에 제외한다. 상위 후보의 정밀 탐색부터 wall centerline, hybrid 손실, 방향 및 선분 이탈 조건을 함께 사용한다.

### 3.5 지도 밖 이탈과 벽 방향 평가

정밀 탐색의 최종 점수는 다음과 같이 구성된다.

\[
L_{\text{score}}
= L_{\text{geometry}}
+ 0.10\text{ m}\cdot r_{\text{outside}}
+ 0.03\frac{\text{m}}{\text{rad}}\cdot e_{\theta}
\]

- \(r_{\text{outside}}\): 지도 밖으로 나간 LiDAR 점의 비율
- \(e_{\theta}\): scan 선분과 지도 벽 방향 사이의 길이 가중 중앙 오차

지도 밖 이탈점은 최대 10 cm에 해당하는 감점을 받는다. 벽 방향은 거리 점수가 비슷한 후보 사이의 우선순위를 결정한다. 방향 항이 더 좋은 후보를 선택하더라도 거리 점수가 0.5 mm 이상 나쁜 후보를 선택하지 않도록 제한했다.

### 3.6 연속 선분 이탈 감점

개별 점 몇 개가 아니라 선분 전체가 지도 벽에서 벗어나는 경우를 별도로 검사한다.

1. 선분별 거리 오차의 75 percentile을 계산한다.
2. 4 cm를 초과한 부분만 이탈량으로 계산한다.
3. 선분 길이로 가중 평균한다.
4. 최종 값이 1.5 cm를 넘으면 후보를 탈락시킨다.

이 값은 손실함수에 단순 가산하지 않고 최종 통과 조건으로 사용한다. 고립된 이상점에는 둔감하고, 선분 전체가 잘못 맞은 경우에는 강하게 반응한다.

### 3.7 손실값에서 구조 검증으로 확장

최종 자세 후보는 다음 조건을 모두 통과해야 한다.

| 검증 항목 | 현재 기준 |
| --- | ---: |
| 5 cm 이내 일치점 비율 | 65% 이상 |
| 전역 탐색 평균 잔차 | 0.020 m 이하 |
| 정밀 탐색 평균 잔차 | 0.018 m 이하 |
| 벽 방향 오차 | 4.5도 이하 |
| 연속 선분 mismatch | 0.015 m 이하 |

평균 손실 하나로 자세를 결정하지 않고 거리, 일치 비율, 방향, 선분 연속성을 함께 확인한다.

### 3.8 단일 scan에서 시간적 합의로 확장

한 번의 scan 결과는 동적 장애물이나 반사 노이즈에 영향을 받을 수 있다. 현재는 최근 3회 결과 중 2회 이상이 다음 범위에서 일치해야 initial pose로 인정한다.

- 위치 차이: 0.08 m 이하
- 회전 차이: 3도 이하

첫 scan에서는 지도 전체를 탐색하고, 두 번째 scan에서는 상위 4개 후보만 새 관찰로 다시 평가한다. 후보가 품질 기준을 통과하지 못하거나 시간 합의가 정체되면 지도 전체 탐색으로 돌아간다. 단일 scan 확정보다 안전하고, 지도 전체 탐색을 세 번 반복하는 방식보다 빠르다.

## 4. 엔지니어링적 타협 변화

### 4.1 로봇 이동 대신 정지 상태 탐색

위치가 불확실한 상태에서 로봇을 회전시키면 안전성과 재현성이 떨어진다. 현재는 로봇을 움직이지 않고 지도 전체 scan matching과 AMCL `/request_nomotion_update`를 수행한다.

안전한 정지 상태를 유지하는 대신 계산시간이 늘어나는 선택이다.

### 4.2 지도 전체 탐색과 정밀 탐색 분리

| 단계 | 위치 간격 | 회전 간격 | 주요 관찰 |
| --- | ---: | ---: | --- |
| 전역 coarse | 0.10 m | 5도 | 벽 선분, occupied surface |
| 상위 후보 refinement | 0.01 m | 0.2도 | 벽 선분, 중심선, 방향 |

전역 탐색에서 상위 4개 후보만 남기고 각 후보를 정밀 탐색한다. 현재 지도는 약 `2.22 × 2.24 m`, 해상도는 `0.02 m`다. 설정값으로 계산하면 한 scan에서 약 19,872개의 coarse 자세와 refinement를 포함한 약 41,280개의 자세 후보를 평가한다.

탐색 격자와 상위 후보 수는 유지하되 계산 경로를 바꿨다.

- 지도 distance field 최대 4개 캐시
- 전역 입력 180점 제한
- 사람과 짧은 불연속 관찰을 전역 탐색 전에 제거
- 같은 회전각의 위치 후보를 NumPy 배열로 한 번에 평가
- coarse 단계에서 방향 계산 생략
- 상위 4개 후보만 refinement
- 첫 scan 이후에는 상위 후보만 새 scan으로 재평가
- 재평가 실패 또는 합의 정체 시 지도 전체 탐색으로 복귀

구현 전에는 3회 확인을 위해 약 123,800개의 자세를 반복 평가했다. 현재 정상 경로에서는 첫 scan의 약 41,280개 자세와 다음 scan의 상위 후보 4개만 평가한다. 첫 scan의 탐색 범위는 줄이지 않았으므로 속도 향상을 위해 정답 후보를 임의로 버리지 않는다.

### 4.3 수렴 안정성과 대기시간 조정

초기 안정화 단계에서는 정밀 수렴에 10개 샘플을 요구했다. 현장 대기시간과 센서 노이즈를 반영해 현재는 6개로 줄였다.

| 항목 | 초기 안정화 설정 | 현재 설정 |
| --- | ---: | ---: |
| fine 수렴 샘플 | 10 | 6 |
| 이론적 샘플 관찰 구간 | 약 9초 | 약 5초 |
| 정밀 평균 잔차 | 0.015 m | 0.018 m |
| 벽 방향 한계 | 3도 | 4.5도 |

샘플 관찰 구간은 약 44.4% 줄었다. 최소 안정 시간 3초, covariance, 위치 jitter와 회전 jitter 검증은 유지했다. 조건을 단순히 완화한 것이 아니라 정답 자세가 센서 노이즈 때문에 반복 탈락하는 현상을 줄인 조정이다.

현재 fine 수렴 조건은 다음과 같다.

| 항목 | 현재값 |
| --- | ---: |
| 연속 샘플 수 | 6 |
| 샘플 간격 | 약 1초 |
| 최소 안정 시간 | 3초 |
| 위치 jitter | 0.08 m 이하 |
| 회전 jitter | 0.15 rad 이하 |
| x/y covariance | 0.25 이하 |
| yaw covariance | 0.35 이하 |
| 전역 탐색 제한시간 | 120초 |
| 전체 위치추정 제한시간 | 180초 |

### 4.4 연속 scan-map 보정 비활성화

현재 TB1과 TB2 설정은 같다.

- `map_wide_scan_matching = true`
- `scan_map_alignment.enabled = false`

손실함수 기반 scan matcher는 초기 위치를 모르거나 위치를 잃은 상태에서만 사용한다. 위치가 확정된 뒤에는 AMCL과 freshness, covariance, jitter 검증으로 주행 가능 여부를 판단한다.

연속 보정은 계산 비용이 크고, 주행 중 일시적인 scan 불일치가 전체 작업을 막는 조건이 될 수 있었다. 알고리즘을 제거하지 않고 효과가 가장 큰 초기 위치 복구 단계로 적용 범위를 제한했다.

### 4.5 EKF 기본 비활성화

wheel odometry와 IMU를 결합하는 EKF를 시험했지만 현재 기본 실행값은 `WITH_EKF=0`이다. 실험 기능은 유지하되 기본 운용은 검증된 wheel odometry와 AMCL 조합을 사용한다. 통합 요소를 추가해 얻는 이득보다 디버깅 변수와 운용 복잡도가 커지는 것을 피한 결정이다.

## 5. 현재 위치추정 흐름

```text
위치 미확정
  → AMCL particle belief 초기화
  → LiDAR에서 벽 선분과 안정적인 구조 추출
  → 첫 scan으로 지도 전체 coarse scan matching
  → 상위 4개 후보 정밀 탐색
  → 다음 scan으로 상위 후보만 재평가
  → 최근 3회 중 2회 일치 확인
  → 후보 불량·합의 정체 시 지도 전체 탐색 fallback
  → AMCL initial pose 입력
  → 정지 상태 no-motion update
  → 6개 샘플과 3초 안정성 확인
  → freshness·covariance·jitter 검증
  → 위치 확정 및 주행 허용

주행 중
  → AMCL 위치 사용
  → 상태 검증 유지
  → 연속 scan-map 보정은 사용하지 않음
```

## 7. 구현 전후 측정

### 7.1 개선 전 기준

개선 전에는 TB2 성공 로그 26건에서 지도 전체 탐색과 AMCL fine 단계를 분리해 집계했다.

| 구간 | 최소 | 중앙값 | 평균 | 최대 |
| --- | ---: | ---: | ---: | ---: |
| 전체 수렴 | 29.43초 | 43.62초 | 55.21초 | 119.82초 |
| 지도 전체 탐색 | 23.96초 | 29.44초 | 29.45초 | 38.61초 |
| AMCL fine 수렴 | 1.88초 | 8.70초 | 25.76초 | 91.09초 |

지도 전체 탐색은 같은 격자 탐색을 scan마다 반복했기 때문에 24~31초의 고정 비용이 발생했다. 전체 시간의 큰 편차는 이후 AMCL fine 단계에서 발생했다. 느린 실행에서는 scan message filter drop과 scan·TF 시각 불일치가 반복됐다.

### 7.2 개선 후 실차 측정

최종 설정은 `벽 선분 필터 → 벡터화된 전체 탐색 1회 → 후보 재평가 → 2-of-3 합의 → AMCL fine`이다. 2026년 7월 20일 TB2에서 로봇을 움직이지 않고 다시 측정했다.

| 실행 | 지도 전체 탐색 | AMCL fine | 전체 | 비고 |
| --- | ---: | ---: | ---: | --- |
| 스택 기동 직후 | 1.16초 | 약 22.8초 | 약 24초 | Nav2 lifecycle 활성화와 scan queue drop이 함께 발생 |
| 기동 완료 후 재측정 | **0.62초** | **6.41초** | **7.02초** | `motion_started=false`, 정상 수렴 |

개선 전 가장 빠른 성공 사례와 기동 완료 후 재측정을 비교하면 다음과 같다.

| 지표 | 개선 전 최저 | 개선 후 재측정 | 변화 |
| --- | ---: | ---: | ---: |
| 지도 전체 탐색 | 23.96초 | 0.62초 | **97.4% 감소, 38.8배 단축** |
| 전체 위치추정 | 29.43초 | 7.02초 | **76.1% 감소, 4.19배 단축** |

개선 후 값은 아직 1회의 정밀 재측정과 1회의 스택 기동 기록이다. 개선 전 26건 분포와 같은 통계적 표본으로 볼 수는 없다. 다만 가장 빨랐던 기존 실행보다 지도 전체 탐색이 23초 이상 짧아졌고, 스택 기동 직후에도 전역 후보는 1.16초 만에 결정됐다. 반복 전역 탐색이 병목이었다는 판단은 실차 결과로 확인됐다.

### 7.3 계산 최적화와 이상치 제거의 영향 분리

두 변경의 목적은 다르다. 벡터화는 같은 계산을 빠르게 수행하기 위한 변경이고, 벽 선분 필터는 전역 후보에 들어가는 관찰을 안정화하기 위한 변경이다.

| 검증 | 변경 전 | 변경 후 | 결과 |
| --- | ---: | ---: | --- |
| 합성 지도 단일 전체 탐색 | 순차 계산 7.1924초 | 벡터 계산 0.6291초 | 11.43배 단축, 최종 자세 차이 0 |
| 실차 scan 원본 관찰 수 | 397점 | 벽 선분 349점 | 48점, 12.1% 제거 |
| 실차 scan 입력 상한 적용 | 180점 | 180점 | 계산량 상한 유지 |
| 실차 scan 전역 탐색 중앙시간 | 0.7972초 | 0.8026초 | 0.0055초 증가 |
| 실차 scan 최종 후보 | 기준 자세 | 동일 자세 | 위치·점수 변화 없음 |

벽 선분 필터는 이 실차 scan에서 12.1%의 짧거나 불연속적인 관찰을 제거했다. 처리시간 증가는 약 0.7%였고 최종 후보는 변하지 않았다. 즉 이번 변경은 속도를 더 줄이기 위한 것이 아니라, 사람과 비벽 관찰이 많은 장면에서 전역 후보가 흔들릴 가능성을 낮추는 타협이다.

### 7.4 정확도 대체 지표

외부 ground truth 장비를 사용하지 않았으므로 절대 위치 정확도라고 표현할 수는 없다. 대신 지도 정합 품질, AMCL 기준 자세와의 차이, 수렴 후 안정성을 확인했다.

| 지표 | 측정값 | 통과 기준 |
| --- | ---: | ---: |
| 전역 후보 평균 잔차 | 0.0141 m | 0.020 m 이하 |
| 5 cm 이내 일치점 비율 | 88.9% | 65% 이상 |
| 연속 선분 mismatch | 0.0050 m | 0.015 m 이하 |

모든 구조 조건과 수렴 조건을 통과했다. 벽 선분 필터 적용 전후의 동일 scan A/B에서도 최종 자세와 점수가 같았다. 현재 자료에서 확인할 수 있는 범위에서는 이상치 제거가 정답 후보를 바꾸지 않으면서 입력 관찰만 정리했다.

### 7.5 병목의 이동

7.02초 실행에서 지도 전체 탐색은 전체의 8.8%, AMCL fine은 91.2%를 차지했다. 개선 전에는 전역 탐색 자체가 최소 23.96초였지만 현재는 1초 안팎으로 끝난다. 다음 개선 대상은 더 이상 전역 matcher가 아니라 다음 항목이다.

- Nav2 기동과 위치추정을 동시에 수행할 때 발생하는 scan queue 적체
- AMCL no-motion update 이후 새 sample 대기시간
- scan header stamp와 TF cache 시간축 불일치
- 기동 직후와 기동 완료 후 수렴시간 차이

전역 탐색은 목표 수준에 도달했다. 전체 수렴시간을 더 줄이려면 fine 단계의 데이터 신선도와 실행 순서를 다뤄야 한다.

## 8. 다음 개선 방향

### 8.1 이번 단계에서 끝낸 개선

기존 병목은 약 41,280개의 자세 후보를 scan마다 다시 평가한다는 점이었다. 시간 합의를 세 번 수행하면 약 123,800개의 자세 평가가 필요했다. 이번 변경에서는 탐색 범위와 상위 후보 수를 줄이지 않고 계산 구조를 바꿨다.

```text
벽 선분만 선별
  → 첫 scan에서 전체 탐색 1회
  → 같은 회전각 후보를 NumPy로 일괄 평가
  → 상위 4개 후보 정밀 탐색
  → 다음 scan에서는 상위 후보만 재평가
  → 최근 3회 중 2회 합의
  → 후보 불량 또는 합의 정체 시 전체 탐색 fallback
```

구현 전에는 지도 전체 탐색을 8~12초까지 줄이는 것을 1차 목표로 잡았다. 실제 실차 재측정은 0.62초였고, 스택 기동 직후에도 1.16초였다. 전체 수렴시간도 기존 최저 29.43초에서 7.02초로 줄었다. 전역 탐색 반복을 제거하고 벡터화한 효과가 최초 목표를 넘어선 셈이다.

### 8.2 탐색 범위를 유지한 이유

후보 수나 격자 해상도를 줄이면 계산량은 쉽게 감소한다. 그러나 대칭 구조가 있는 실내 지도에서는 정답 후보도 함께 제거될 수 있다.

- 상위 후보를 4개에서 2개로 줄인 시험: 7.88초에서 4.52초로 단축됐지만 잘못된 대칭 위치가 통과
- 위치·회전 격자를 더 거칠게 만든 시험: 정답 주변 후보를 놓침
- 최종 선택: 탐색 공간은 유지하고, 평가 연산과 반복 횟수만 축소

속도를 위해 정답 가능성을 줄이는 대신 같은 탐색 범위를 더 빠르게 계산했다. 이번 개선의 핵심적인 엔지니어링 타협이다.

### 8.3 Multi-resolution Branch-and-Bound의 역할

Branch-and-Bound는 정확도를 대신하는 손실함수가 아니라, 주어진 점수에서 최적 후보를 더 적은 계산으로 찾는 탐색 기법이다. 입력에 사람과 비벽 관찰이 남아 있거나 점수함수가 장면을 잘 구분하지 못하면, Branch-and-Bound도 그 점수에서 가장 높은 오답을 빠르게 찾을 수 있다.

따라서 대형 지도로 확장할 때의 권장 구조는 다음과 같다.

```text
이상치·비벽 관찰 제거
  → 단순한 correlative score로 Multi-resolution Branch-and-Bound
  → 상위 후보만 현재 hybrid 손실로 재평가
  → 벽 방향·연속 선분 mismatch 검증
  → 후속 scan 시간 합의
```

trimmed Huber처럼 일부 관찰을 정렬한 뒤 제거하는 손실은 구간의 최대 가능 점수를 단순하게 계산하기 어렵다. 이를 pruning 기준에 직접 넣기보다, 더하기 쉬운 correlative score로 탐색하고 현재의 강건 손실은 상위 후보 검증에 사용하는 편이 안전하다.

현재 지도에서는 전체 탐색이 0.62~1.16초이므로 Branch-and-Bound가 당장의 병목 해결책은 아니다. 지도 면적이나 회전 해상도가 커져 전역 탐색 시간이 다시 수 초 이상으로 증가할 때 적용하는 확장안이 적절하다.

### 8.4 warm restart의 우선순위

스택만 재시작되고 로봇이 움직이지 않았다면 마지막 검증 자세 주변부터 탐색하는 warm restart를 사용할 수 있다. 다만 현재 전체 탐색 비용은 1초 안팎이므로 이를 생략해 얻는 이득보다 저장 자세의 유효성 판단과 잘못된 자세 재사용 위험이 더 크다.

warm restart는 빈번한 스택 재시작이 실제 운용 병목으로 확인될 때 추가한다. 적용할 경우 저장 시각, 로봇 이동 가능성, 현재 scan 구조 검증을 모두 통과해야 하며, 하나라도 실패하면 현재의 지도 전체 탐색으로 복귀해야 한다.

### 8.5 다음 병목: AMCL fine 단계

기동 완료 후 재측정에서 전역 탐색은 전체 7.02초 중 0.62초였고, AMCL fine은 6.41초였다. 현재 우선순위는 전역 탐색을 더 줄이는 것이 아니라 기동 상태와 scan·TF 시간축을 안정화하는 것이다.

1. AMCL과 TF가 활성화된 뒤 자동 전역 탐색을 시작하도록 기동 순서를 고정한다.
2. matcher 실행 중 쌓인 scan을 순서대로 처리하지 않고 최신 scan을 우선하는 방식을 검토한다.
3. scan 수신 시각, header stamp, TF 기준 시각의 차이를 매 실행에 남긴다.
4. no-motion update 이후 실제 AMCL sample 도착 간격과 callback 지연을 측정한다.
5. 전역 탐색 시간과 fallback 횟수가 최종 상태 응답에서도 유지되도록 계측 정보를 보존한다.

다음 검증은 단일 최저값보다 반복성을 확인하는 방식으로 진행한다.

| 검증 목표 | 기준 |
| --- | ---: |
| 정지 상태 반복 측정 | 10회 이상 |
| 위치확정 성공률 | 100% |
| 지도 전체 탐색 중앙값 | 1.2초 이하 |
| 전체 수렴 중앙값 | 8초 이하 |
| 전체 수렴 95 percentile | 10초 이하 |
| 구조·정확도 대체 지표 | 현재 통과 기준 유지 |

이 기준을 안정적으로 통과한 뒤에만 fine sample 간격이나 확인 횟수를 줄이는 추가 최적화를 검토한다. 속도를 더 얻기 위해 안정성 조건부터 완화하지 않는 순서다.

## 9. 연구 흐름과 현재 구현의 위치

### 9.1 AMCL에서 손실함수로 교체됐다는 해석

기술 흐름을 `AMCL → 손실함수 방식`으로 표현하는 것은 정확하지 않다. AMCL도 LiDAR 관찰의 likelihood를 계산하는 관찰모델을 사용한다. 이후 연구는 AMCL을 일괄 폐기하기보다 다음 요소를 결합하는 방향으로 발전했다.

1. MCL 또는 필터 기반 확률 추적
2. 전역 후보를 찾는 scan matching 또는 place recognition
3. 거리·방향·특징을 이용한 정밀 정합
4. 동적 물체와 이상치를 억제하는 강건한 관찰모델
5. 시간적 일관성과 불확실도를 이용한 신뢰도 판단

현재 구현은 학습 모델 없이 위 구조를 구성한 classical hybrid localization에 가깝다.

| Robust MCL, 2001 | dual sampling으로 혼잡 환경과 위치 손실 복구 강화 | 별도 전역 후보를 AMCL에 다시 공급하는 구조와 목적이 유사 |
| Correlative Scan Matching, 2009 | 사전 위치가 약한 상황에서 넓은 영역의 scan 정합을 직접 평가 | 현재 지도 전체 격자 탐색과 직접 연결 |
| Cartographer, 2016 | 사전 계산 grid와 Branch-and-Bound로 전역 scan matching 가속, local·global 정합 분리 | 다음 전역 탐색 고속화안의 직접 근거 |
| Reliable MCL, 2022 | pose tracking, 신뢰도 판단, global localization을 결합하고 실패 시 빠르게 복구 | AMCL 추적, localization gate, 실패 시 전역 복구 구조와 유사 |

### 9.3 최근 연구와 유사점

| 연구 | 공통점 | 차이점 |
| --- | --- | --- |
| Generalizable Stable Points Segmentation, 2024 | 불안정한 점을 제외하고 안정적인 구조만 scan-to-map 정합에 사용 | 논문은 3D LiDAR와 학습 기반 분할, 현재 구현은 2D 선분 길이·직선성 기반 필터 |
| Reliable-loc, 2024 | 공간 구조로 후보를 검증하고 연속 관찰과 불확실도로 위치추정 모드를 전환 | 논문은 대규모 3D 야외 지도와 학습 특징, 현재 구현은 2D 벽 구조와 2-of-3 합의 |
| Efficient Neural Map MCL, ICRA 2025 | 거리와 방향 정보를 함께 표현한 관찰모델을 기존 MCL 안에서 사용 | 논문은 signed distance와 방향을 neural map으로 학습, 현재 구현은 distance field와 벽 tangent를 직접 계산 |
| Coarse-to-Fine MCL-DLF, 2025 | 전역 coarse 위치추정과 정밀 registration을 분리 | 논문은 3D LiDAR와 deep feature, 현재 구현은 2D 점유지도와 강건 손실함수 |

ICRA 2025의 Efficient Neural Map MCL은 현재 구현과 개념적으로 가장 가까운 비교 대상이다. 이 연구는 2D LiDAR 관찰에 대해 거리와 방향 정보를 함께 예측하고 이를 MCL 관찰모델에 사용한다. 현재 구현도 지도 distance field로 거리 오차를 계산하고 벽 tangent로 방향 오차를 계산한다. 차이는 논문이 이를 neural implicit map으로 학습한다는 점이고, 현재 구현은 점유지도와 skeleton에서 결정론적으로 계산한다는 점이다.

Reliable-loc과 현재 구현은 공간 검증과 시간 검증을 함께 사용한다는 점이 유사하다. 현재의 match ratio, 벽 방향, 선분 mismatch는 공간 검증에 해당하고, 2-of-3 합의와 covariance·jitter gate는 시간 검증 및 상태 판단에 해당한다.

최근 연구와 비교했을 때 현재 구현을 다음과 같이 정리할 수 있다.

> AMCL 기반 추적 위에 학습 없는 강건한 전역 scan matcher, 구조 검증, 시간적 신뢰도 판단을 결합한 하이브리드 위치추정 구조

## 10. 결론

초기 위치추정은 AMCL에 수동 initial pose를 입력하는 방식에서 시작했다. 이후 LiDAR와 지도를 직접 비교하는 전역 탐색을 추가하고, 손실함수를 거리 평균에서 trimmed Huber와 hybrid 구조로 확장했다. 관찰 대상도 개별 점에서 벽 선분으로 바뀌었고, 지도 밖 이탈, 벽 방향, 연속 선분 mismatch, 시간적 합의가 추가됐다.

마지막 개선에서는 손실 항을 계속 늘리는 대신 역할을 분리했다. 전역 탐색 전에는 비벽 관찰을 제거하고, 넓은 후보 평가는 벡터화된 강건 거리 점수로 처리하며, 계산량이 큰 방향과 선분 검증은 상위 후보에만 적용한다. 첫 전체 탐색 뒤에는 후보만 다시 평가하되 품질이 떨어지면 전체 탐색으로 돌아간다. 이 구조로 전역 탐색은 기존 최저 23.96초에서 0.62초, 전체 위치확정은 29.43초에서 7.02초로 줄었고 구조 검증 기준은 유지됐다.

운용 단계에서도 복잡한 계산을 항상 적용하지 않는다. 지도 전체 matcher는 초기 위치 복구에 집중시키고, 주행 중에는 AMCL과 상태 검증을 사용한다. 현재 설계의 핵심은 높은 정밀도의 알고리즘을 계속 실행하는 것이 아니라 필요한 단계에 배치해 정확도, 계산량, 안전성 사이의 균형을 맞추는 것이다. 다음 개선의 중심은 전역 탐색이 아니라 AMCL fine 단계와 기동 직후 scan·TF 동기화다.
