# GPT 전달용 이동 서버 발표자료 최종 브리프

아래 내용을 그대로 GPT에 전달해 발표자료를 작성한다.

## GPT 작업 지시

`AutoPilot_E2E_발표구성_가이드_v1.pptx`의 전체 디자인과 발표 흐름은 유지하되, 이동 서버 파트와 통합 결과 파트를 아래 사실만 사용해 최신화해 주세요.

- 청중: 교수, 심사위원, 개발자
- 발표 목표: 기능 나열보다 실물 문제를 어떻게 진단하고 운영 가능한 시스템으로 해결했는지 보여주기
- 분량: 이동 서버 핵심 5장 + 통합 결과 2장 + 결론 1장
- 문장: 슬라이드당 핵심 메시지 1개, 본문 4줄 이내
- 시각 자료: 구조도, 단계 흐름, 문제-해결 표, 실물 영상 캡처 우선
- 사실이 아닌 과장 표현은 사용하지 않기

## 한 줄 핵심 메시지

> Main의 물류 업무 명령을 Nav2 주행, ArUco 정밀 정렬, 리프트 작업, 복귀와 상태 callback으로 변환하는 두 대의 실물 로봇 이동 서버를 구현했다.

## 슬라이드 1 — 이동 서버의 역할

제목: `업무 명령을 실제 로봇 동작으로 변환`

- Main은 로봇, 입고·창고·출고 위치, 층과 작업 의미만 전송
- Movement는 좌표, marker ID, 접근 거리, 정렬 기준, 리프트 높이를 관리
- Main을 수정하지 않고 로봇별 물리 보정값을 변경 가능
- `202 Accepted`와 실제 완료 callback을 분리

권장 그림:

```text
Main → Scenario API → Nav2 / ArUco / Lift → Robot → Callback
```

발표 멘트:

> Main은 어디서 무엇을 옮길지만 결정하고, 실제로 어떻게 움직일지는 이동 서버가 책임집니다.

## 슬라이드 2 — 두 로봇 분리 구조

제목: `한 서버에서 두 로봇을 독립적으로 운용`

| 구분 | 로봇1 | 로봇2 |
|---|---:|---:|
| ROS domain | 2 | 5 |
| Movement API | 8001 | 8002 |
| 대기장소 | 대기1, marker 3 | 대기2, marker 4 |
| 물리 프로필 | 5cm marker, 1층 운반 8mm | 검증된 로봇2 프로필, 1층 운반 6mm |

- 로봇별 Nav2, AMCL, 카메라, 리프트 연결 분리
- Scenario API가 명령받은 로봇에 맞춰 복귀 위치와 marker를 자동 선택

## 슬라이드 3 — 물류 실행 알고리즘

제목: `장거리 Nav2와 근거리 ArUco의 역할 분리`

```text
준비 상태 확인
→ Nav2 접근
→ ArUco 중앙·면각·거리 정렬
→ 3초 안정화
→ 20cm급 정밀 접근
→ 리프트 작업
→ 실제 삽입량 기반 후진
→ 지정 대기장소 복귀
```

핵심 수치:

- ArUco 카메라 보정 RMS: 0.133px
- 정밀 접근: 40cm 1차 접근 후 20cm급 최종 접근
- 창고 A·B: 실물 보정값 18cm 유지
- 로봇1 marker yaw 허용값: 6°
- 로봇1 1층 적재·운반 높이: 8mm

## 슬라이드 4 — Scenario API와 18단계

제목: `하나의 업무 요청을 검증된 물리 단계로 확장`

- Main 업무 진행 상태: 입고 9단계 + 출고 9단계 = 총 18단계
- Movement 내부: 입고 또는 출고 시나리오 하나를 18개 물리 단계로 실행
- 등록된 위치 조합은 같은 Nav2·ArUco·Lift 알고리즘으로 생성
- 생성 가능과 모든 조합의 실물 성공은 구분

예시:

```text
창고 D → 출고1 → 대기장소1
```

Main은 위치 이름만 보내고, Movement가 marker 10·marker 5·marker 3과 각 보정값을 적용한다.

## 슬라이드 5 — 대표 문제와 해결

제목: `실물 실패를 시스템 개선으로 전환`

| 문제 | 원인 | 해결 |
|---|---|---|
| 카메라 불안정 | libcamera/IPA 충돌 | Picamera2 기반 ROS 영상 발행 |
| 벽 접촉·거리 편차 | 픽셀 폭과 공통 거리 | calibrated metric distance와 구역별 보정 |
| 후진 실패 | 잘못된 reverse 매핑 | `reverse_out`과 실제 삽입량 기반 후진 |
| 재부팅 후 주행 불가 | OpenCR USB·AMCL 위치 불일치 | USB topology 검증, readiness, initial pose 복구 |
| 로봇1 잘못된 복귀 | 로봇2 대기장 템플릿 고정 | 로봇별 복귀 waypoint와 marker 자동 선택 |
| 리프트 적재 부족 | 로봇1 실물 높이 부족 | 로봇1만 6mm에서 8mm로 보정 |

폐기·보류한 방식:

- 픽셀 폭만으로 최종 거리 판단: 폐기
- 모든 구역 동일 삽입 거리: 폐기
- EKF 상시 사용: 실물 결과가 혼재해 기본값 `WITH_EKF=0`
- 중앙 Supervisor: 운영 복구가 어려워 7-pane 방식 유지
- 중앙 다중 로봇 planner·공용 costmap: MVP 범위에서 제외

## 슬라이드 6 — 실물 최종 결과

제목: `대표 물류 시나리오 실물 완주`

로봇1 최신 대표 성공:

- 2026-07-21 `창고 D 적재 → 출고1 하역 → 대기장소1 복귀`
- 최종 상태 `DONE`
- 리프트 8mm 적재·운반 성공
- 출고1 정밀 정렬과 하역 성공
- marker 3 기반 대기장소1 주차 성공
- `cargo_state=EMPTY`, `business_completed=true`, authority 반환 완료
- 검증 명령 ID: `video-tb3_1-storage-d-outbound1-8mm-return-wait1-20260721-010`

로봇2 대표 성공:

- `입고2 → 창고 A → 대기2`
- `창고 A → 출고2 → 대기2`
- 과거 실물 성공 흐름: `입고2 → 창고 B → 출고1 → 대기2` 등

표현 원칙:

> 등록 경로는 시나리오로 생성할 수 있고, 대표 시나리오는 실물로 완주했다.

## 슬라이드 7 — 두 대 충돌 방지

제목: `공용 통로는 traffic lock으로 순차 진입`

```text
로봇1이 warehouse_aisle lock 획득
→ 로봇2 요청은 409 WAITING_TRAFFIC
→ 로봇1 완료 후 lock 해제
→ Main이 새 command_id로 로봇2 재전송
→ 로봇2 주행
```

- 공용 구간: `inbound_lane`, `warehouse_aisle`, `outbound_lane`
- 두 이동 서버가 공용 lock 상태를 사용
- LiDAR, Nav2 costmap, collision monitor는 로봇별 마지막 안전장치
- 현재는 lock 발생 시 자동 우회가 아니라 안전한 순차 재배차 방식

발표 멘트:

> 두 로봇이 우연히 부딪히지 않은 것이 아니라, 공용 통로를 한 대만 점유하도록 명령 수락 단계에서 차단합니다.

## 슬라이드 8 — 결론

제목: `실물 튜닝을 감춘 반복 가능한 물류 실행`

- Main 업무 의미와 로봇 물리 튜닝 분리
- Nav2·ArUco·Lift를 하나의 시나리오로 통합
- 준비 상태, 실패 원인, callback, 멱등성까지 포함한 실행 계약
- 두 로봇의 독립 실행과 공용 구간 충돌 제어 구현

마지막 문장:

> 단순히 로봇을 움직인 것이 아니라, 반복되는 실물 실패를 측정하고 복구 가능한 물류 실행 시스템으로 만들었습니다.

## 영상 배치

1. 로봇1 `창고 D → 출고1 → 대기1` 성공 영상
2. 로봇2 검증된 대표 E2E 영상
3. traffic lock 영상: 한 대 주행, 다른 한 대 `WAITING_TRAFFIC`, 완료 후 재전송
4. 가능하면 Main 화면의 command ID, `ACCEPTED`, `DONE`을 영상과 함께 표시

## 반드시 피할 표현

- 모든 등록 조합을 실물로 성공했다
- 두 로봇이 서로를 완전히 인식해 어떤 상황에서도 자동 회피한다
- traffic lock 발생 시 다른 통로로 자동 우회한다
- EKF가 현재 운영 기본값이다
- Main이 좌표·marker·리프트 높이를 직접 보낸다
- 18단계가 입고 18 + 출고 18개의 Main 업무 단계라는 표현

정확한 표현:

- Main 업무 단계는 입고 9 + 출고 9 = 총 18단계
- Movement 내부 물리 실행은 시나리오당 18개 단계로 확장될 수 있음
- 두 로봇 충돌 제어는 공용 구간 lock과 Main 재시도 방식
- 대표 시나리오 실물 성공과 등록 경로 생성 검증을 구분
